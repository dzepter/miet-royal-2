# Pilot-Zielsystem auf dem MacBook (Phase 19 – Fortsetzung)

Dieses Verzeichnis ist das versionierte Betriebs-Kit für den dauerhaft laufenden MacBook-Pilot
von Miet-Royal 2.0: Installation, Konfiguration ohne Secrets, Deployment mit Rollback,
Backup/Restore, launchd-Autostart, Caddy-Reverse-Proxy, Watchdog und Prüfskripte. Es enthält
**keine Secrets** und **keine Rechnerdaten** – beides entsteht erst auf dem Mac
(`secrets/`, `docs/PILOT_MACBOOK_INVENTORY.md` über `inventory.sh`).

Ziel-Topologie (docs/ARCHITECTURE.md, Phase-19-Topologie): Internet → STRATO-DynDNS →
Heimrouter (nur TCP 80/443) → MacBook → Caddy → `pilot.miet-royal.de` (Web + Kundenportal),
`staff-pilot.miet-royal.de` (Staff), `api-pilot.miet-royal.de` (nur Direktrouten:
`/webhooks/*`, `/public/calendar/*`, `/health`, `/ready`). Alle Anwendungsprozesse und
PostgreSQL lauschen ausschließlich auf `127.0.0.1`.

## Verzeichnisstruktur auf dem Mac (`MR_BASE`)

```
MR_BASE/
  repo.git/                 Bare-Mirror von origin (nur Quelle für Releases)
  releases/<git-sha>/       vollständiger Release-Baum (Quellcode, node_modules, .next)
  current -> releases/<sha> aktives Release (atomar gesetzter Symlink)
  previous -> releases/<sha> letztes funktionierendes Release (Rollback-Ziel)
  config/pilot.env          Konfiguration OHNE Secrets (640)
  config/caddy/Caddyfile    Reverse-Proxy
  config/offsite.conf       Off-site-Ziel (Host, Benutzer, Pfad; kein Secret)
  config/backup-recipients.txt  age-Empfänger (öffentliche Schlüssel)
  secrets/pilot.secrets.env Secrets (600; nur configure-secrets.sh schreibt)
  secrets/backup-age.key    age-Identität der Automation (600)
  secrets/offsite_ed25519   SFTP-Schlüssel (600)
  secrets/dyndns.secret     STRATO-DynDNS-Passwort (600)
  storage/                  Dateispeicher der Anwendung (700)
  backups/<ts>/             Sicherungen (verschlüsselt, .completed-Marker)
  logs/                     Logs aller Dienste (Rotation)
  run/                      Status-/Backoff-Dateien, Lease-Key-Cache
  tmp/                      Arbeitsverzeichnisse (Restore-Test)
  scripts/                  dieses Kit (Kopie aus infra/pilot-macbook/scripts)
```

## Ablauf

1. **Bootstrap (einmalig, im Terminal des Macs, mit sudo-Abfrage):**
   `bash infra/pilot-macbook/bootstrap.sh` – erhebt das Inventar (ohne Seriennummern), installiert
   Homebrew-Pakete, legt die Struktur an, richtet PostgreSQL (nur localhost, scram-sha-256,
   eigener Benutzer, eigene Datenbank) und die Konfigurationsvorlagen ein, installiert die
   LaunchAgents und setzt den Netzbetrieb (`pmset -c`: kein Systemschlaf, Display darf schlafen).
2. **Secrets:** `MR_BASE/scripts/configure-secrets.sh` (interaktiv, Eingabe ohne Echo).
3. **Deployment:** `MR_BASE/scripts/deploy.sh <git-sha|branch>` – Release-Ordner, Install, Builds,
   Preflight, Backup, Migration, Umschalten, Health/Ready/Smoke, bei Fehler automatischer
   Rückfall auf das vorige Release.
4. **Betrieb:** `status.sh`, `pilot-check.sh`, `start.sh`/`stop.sh`/`restart.sh` (`stop.sh` setzt
   die Wartungsmarke `run/maintenance`, der Watchdog startet dann nichts neu), `rollback.sh`,
   `backup.sh`, `backup-offsite.sh`, `backup-verify.sh`, `restore-test.sh`, `watchdog.sh`
   (launchd), `dyndns-update.sh` (launchd, optional), `rotate-logs.sh` (launchd),
   `with-env.sh <befehl>` (ein Befehl mit Pilot-Umgebung, ohne Secrets in der Shell),
   `secret-scan.sh`.

Runbook: docs/PILOT_MACBOOK_RUNBOOK.md. Inventar: docs/PILOT_MACBOOK_INVENTORY.md (vom Mac
erzeugt). Die Skripte sind für macOS `/bin/bash` 3.2 geschrieben (keine Bash-4-Konstrukte) und
nutzen `lib.sh` für BSD/GNU-Unterschiede; sie laufen zur Prüfung auch unter Linux
(Service-Steuerung dann über Fallback-Prozesse statt launchd).
